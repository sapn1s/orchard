# BUG-127 — One ticket's wording can erase rows from the archive index

## Diagnosis

The archive index is generated by pasting values a person wrote into markdown table rows: each archived ticket's H1 title, and, for a ticket named in `--allow-legacy`, the reason it was left behind. Both interpolations escaped one character, `|`, and nothing else.

`|` is only the smallest of the three things that can end a table. A **row** ends at a line break, and a **rendered region** ends at `<`. So:

- A reason or title carrying a newline splits its own row into a half-row followed by loose prose. If that prose contains `## something`, the generated document gains a heading the generator never wrote.
- A reason or title carrying `<!--` opens an HTML comment. In any renderer that passes HTML through — GitHub, where this file is actually read — every row after it disappears until a `-->` that may never come.
- A value already containing `\|` was emitted as `\` + `\|`. The `\\` renders as one literal backslash and leaves the `|` live, so the escape defeated itself.

In every case the promotion exited 0 and reported success.

The pipe escaping does defeat a fabricated row, so this is corruption, not forgery: nobody can invent a ticket that was never archived. What they can do is make a real one invisible.

This is the same class as **BUG-126**, where a severity written as a 200-character sentence wrecked its row in the ticket list. There the value was too long for its cell; here it contains a character that ends the cell. Both are a free-text value written into a fixed cell with no contract about what may be in it.

## Evidence

Both hazards were reproduced on the real corpus before anything was changed, not on a fixture: 194 real archived originals and 194 real records, restored to their pre-promotion positions in a throwaway git repo and promoted by the real `promote()`.

- A reason containing a newline emitted FEAT-091's row as `| FEAT-091 | [link](…) | Contested evidence.` followed by a blank line, a `## Injected heading` H2 and a stray `loose prose that is not a row. |`. `promote()` returned 0.
- A reason containing `<!--` on the alphabetically FIRST legacy row emitted an unterminated comment, with the second legacy row written after it. `promote()` returned 0.

The **rendered** half was checked too, because BUG-126 was invisible in the source and only showed on screen. Both findings above had been graded on markdown source only, and the render splits them:

- The newline hazard is real in this project's own renderer. Driving the corrupted index through `prose()` in a real headless browser produced a legacy table with **one** row, `BUG-125`, where the correct document renders two — and `Injected heading` appeared as a real heading on the page. A reader sees one deliberately-left-behind ticket where there are two, which is exactly the reported symptom.
- The `<!--` hazard is **not** reproducible in this project's renderer. `prose()` inserts every cell as text, so it opens no comment node at all and the `<!--` shows as literal characters. That half of the finding is real on GitHub and in any HTML-passing renderer, and false in-app.

That distinction is worth keeping rather than smoothing over, and it does not weaken the fix: the archive index is a file people read as source and on GitHub, and it is not served by the running app at all. Three routes were probed against a scratch server and none returned it — the guide viewer serves `docs/guide/` and only that.

## Implementation notes

`escapeTableCell` closes the class rather than the two characters that were found. It handles what can end a **cell** (`|`, and `\` before it, in that order), what can end a **row** (`\r\n`, a lone `\r`, `\n`, U+2028 and U+2029), what can end a **rendered region** (`<`, which opens comments, block tags and raw tags alike), and what is invisible in the source at all (the remaining C0/C1 controls — a NUL alone makes the file binary to `grep`, which is BUG-103).

`&` is deliberately not escaped. It cannot terminate a cell, a row or a region, and escaping it would rewrite the three real titles that contain one for no gain. Leaving it alone is also what lets the shipped index regenerate byte-identical, which is the strongest available anti-regression for a fix to a generator whose one real output already exists.

Escaping is lossy — a newline becomes a space — so a rewritten value is now NAMED in the promotion's output on a `CELL ESCAPED` line. Silently rewriting what a person wrote is close to how this got as far as it did. Refusing outright was rejected: a multi-line reason is legitimate to write, it is only illegitimate to emit into a table row unchanged.

### Left for someone else, deliberately

- **`asCell` in `scripts/board.mjs`** has the same missing `<` escape. It collapses whitespace, so the line-break half cannot reach it, but a ticket title containing `<!--` can still open a region in the board index — and unlike `promote()`, that generator runs constantly. It was not touched because another lane holds that file.
- **The half-apply hazard is pre-existing and is not fixed here.** If a `git mv` fails partway through the 194 moves, `promote()` stops with some originals moved and some not. It was proven identical against a pinned pre-change script, so it is not a regression from this work. What it wants is staging as mv-then-rename with a rollback. Note for recovery today: after a SIGKILL, `.git/index.lock` has to be removed before `git reset --hard` will run.

## Verification plan

`npm run verify:bug-127` — 38 assertions over the real corpus, pinned at the cutover commit `f109aa8`.

The pin matters and is not laziness. `promote()`'s gate requires each staged record's activity log to be a byte-for-byte copy of its original's, and the board keeps being worked, so reading the working tree makes the suite go red when someone uses the product correctly. That was measured, not predicted: the first run failed on BUG-124, mid-fix in another lane. A pinned revision also cannot quietly become the fixed state the way `HEAD` does.

Non-vacuity is proven against a **synthesized pre-fix generator** — the shipped file with the two escaping call sites rewritten back — not against `HEAD`, so committing the fix cannot turn the proof into a tautology. Two guards on that proof:

- a **CONTROL** case runs first and must pass: the pre-fix generator has to load, run, and reproduce the shipped index byte-for-byte. Without it, a red below could equally mean the copied module never resolved its imports, and those two are indistinguishable from the output alone. If the control fails the suite refuses to read the reds as a proof at all, rather than banking them.
- each must-FAIL case names the **signature** of the corruption it expects — the injected heading, the opened comment, the comment inside a main-table row — so a variant that failed for some other reason cannot be counted.

`npm run verify:bug-127-render` — 9 assertions in a real browser over the app's own renderer, plus the reachability probe. Free ephemeral port, scratch data dir, processes killed by pid.

## Risks

The escape is applied to a generator whose one real output already exists, and that output is proven to regenerate byte-identical, so the change cannot alter the shipped archive. A future title or reason containing `<` will render as `&lt;` — a literal `<` on screen, one character wider in the source. That is the intended cost.
