# FEAT-125 — Orchard sessions talk too much; enforce reply brevity where every session reads it

- **Status:** VERIFIED — brevity budget injected via RESPONSE_FORMAT.md core; docs-enforcement only, mechanical gate filed as follow-up
- **Severity:** medium
- **Area:** server (templates.ts injection) / docs/prompts (RESPONSE_FORMAT.md core)
- **Reported:** 2026-09-05 by user
- **Verification-class:** docs-only (the change is injected prompt text + its byte-budget assertion; verified by the two existing inject/grammar suites)

## Symptom
User, 2026-09-05: *"every next orchard session does the same, they all talk too
much for no reason."* An independent OpenAI review of 12 real orchestrator
replies found only ~10-60% of each reply was actionable. A per-project memory
file (`orchestrator-output-brevity.md`) records the adopted rules but does NOT
reach new sessions in other projects — memory is per-project, so the rule must
live where every launched session actually reads it.

## Repro
Launch any project session. The brevity rules exist only in one project's memory
dir, so a session in a different project never receives them and pads its replies.

## Expected
The brevity budget is injected into every response-format-enabled session's
system prompt, alongside the response-format core, so it is paid and read on
every turn of every project.

## Context pack
- Injection path: `src/server/templates.ts#responseFormatSection` extracts the

- Budget: `scripts/verify-feat-084-response-format-inject.mjs` asserts the
  injected core ≤ 5900 bytes. Repro/anti-regression tests:
  `npm run` → `node scripts/verify-feat-084-response-format-inject.mjs` and

### Mechanical enforcement — feasibility (report, not built)
A mechanical check is feasible and would hook into the existing Stop-hook
metrics path. `scripts/hooks/response-format-gate.mjs` already runs on every
graded turn and reads the assistant message; adding a prose-word count (blocks
minus the digest/fence wrappers, per the same rule injected) and flagging turns
over the ≤120/≤250 ceiling is a small addition that writes to the same
`response-format-metrics.jsonl` and surfaces in `scripts/lib/format-metrics.mjs
report`. It would be ADVISORY, exactly like the current format gate — it cannot
block generation (the turn is already emitted when Stop fires), so docs get us to
"the rule is present on every turn + measured + a nudge on violation," not to a
hard cap. That is the honest ceiling of enforcement here: injection makes the
rule reach every session; a metrics gate makes over-length turns visible and
countable; neither can truncate a reply mid-generation. Filed as the follow-up.
