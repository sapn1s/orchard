# FEAT-127 — Orchestrator hands the user decisions that are not theirs (and it isn't measured)

- **Status:** FIXED — ownership-test rule added to canonical WA §A (every session reads it); both failure modes now MEASURED per turn in format-metrics. Advisory only; self-verified against a real transcript.
- **Severity:** medium
- **Area:** docs/prompts (canonical Working Agreement §A) / scripts/lib (format-metrics.mjs measurement)
- **Reported:** 2026-09-05 by user
- **Verification-class:** docs-only (injected WA text) + advisory-measurement (format-metrics cannot affect a turn); verified by a real-transcript run of the new metric + the FEAT-091 grammar suite as anti-regression

## Symptom
User, 2026-09-05: *"i could not care less if u tell u wont do it, that has never
worked, hence im asking if we have fixed it for future sessions or need to find
how to fix all this."* Two orchestrator failures the user has named twice, where
promising to behave better has repeatedly failed:

- **(A) writing too much unnecessary info** — already addressed structurally by
  FEAT-125 (brevity budget injected into the RESPONSE_FORMAT.md core). Not redone
  here.
- **(B) handing the user decisions that are not theirs** — NOT addressed anywhere
  that reaches a future session. Concrete instance this session: after building a
  feature the orchestrator asked the user to choose between "carry the ticket id
  onto running lanes", "do steps 3-5", and "prove it end-to-end" — pure
  implementation sequencing the user had no stake in. User's reaction: *"is it
  weird that i have no clue what are u even asking me"* and *"i spent like 10min
  trying to figure it out and its a waste."*

## Why nothing existing covers (B)
- WA §N governs FILE-vs-BUILD, not which decisions belong in a reply.
- The per-project memory `file-only-needs-a-real-reason` is per-project and never
  reaches other sessions.
- WA §A already says "lead with a recommendation" and "if a question has an
  obvious answer, decide" — but it never says an implementation-ordering choice is
  NOT the user's at all. The offending ask had a recommendation; it was still
  illegitimate.

## Fix
1. **The rule, where every session reads it — canonical WA §A** (universal to any
   agent; `~/projects/methodology/WORKING_AGREEMENT.v4.md`, mirrored to
   `docs/prompts/WORKING_AGREEMENT.v4.md` by `npm run sync:methodology`). Extended
   §A rather than duplicating, since §A already owns "lead with a recommendation".
   The rule is TESTABLE per ask, not advice:

   > **Not every question is the user's to answer — apply the ownership test
   > before every ask.** An ask is legitimate ONLY if you can name, in one
   > sentence, both the fork AND the user-held thing that decides it: their taste,
   > priority, spend, risk appetite, or project direction. If you cannot name that
   > thing, it is not their decision — it is yours. **Sequencing, implementation
   > approach, and "which of these should I do first" are never the user's**; pick
   > the best one, note it, proceed. Handing over an implementation-ordering choice
   > (…) is the neutral-menu defect wearing the costume of deference (…). This is
   > checkable per ask, by you or an auditor: no nameable user-held decider →
   > delete the ask and decide.

2. **Both failure modes made MEASURABLE** (`scripts/lib/format-metrics.mjs`),
   since discipline has failed twice. FEAT-125 concluded the Stop hook
   (`scripts/hooks/response-format-gate.mjs`) already parses each main-thread
   turn's blocks and can measure but not truncate. Per graded turn the record now
   carries `proseWords` (words a reader reads — every category block body plus
   loose prose, EXCLUDING the `orchard-digest` JSON and fence wrappers) and
   `askBlocks` (count of `orchard-ask`). `format-metrics.mjs report` gains a
   **PROSE VOLUME & ASKS** section: mean/median/max prose words, turns over the
   120-word default budget and over the 250-word handoff cap, total asks,
   asks-per-turn, turns with >=1 ask and turns with MORE THAN ONE ask, and the
   biggest prose turns. **Advisory by nature** — it records numbers, it cannot
   block or truncate a turn. It is a lens on the transcript, not enforcement, and
   is stated as such in the code and the report header.

## What was NOT done, deliberately
- RESPONSE_FORMAT.md core was left untouched: the injected core is at 5880 B
  against a 5900 cap (no room), and the ownership rule is universal, so its home is
  the WA, not the format core. The core's `orchard-ask` definition ("an action
  only you can take") already gestures at ownership; the WA carries the testable
  rule.
- The metric is advisory. A mechanical length/ask gate that costs a turn is not
  built here (and per FEAT-085's history a turn-costing gate mis-fires on a
  read-during-write race).
