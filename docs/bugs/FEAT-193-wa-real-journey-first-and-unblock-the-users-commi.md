# FEAT-193 — WA: real-journey-first for journey defects, and unblock the user's commit before verification

- **Status:** DONE
- **Severity:** medium
- **Area:** methodology / process (WORKING_AGREEMENT.v4)
- **Reported:** 2026-10-25 by orchestrator (history study of BUG-268/269/270/271/272)
- **Verification-class:** docs-only ⟶ no independent clean-room verification required
  (a prose/process change to the Working Agreement; the gates below are the proof bar).

## Symptom
Two recurring, evidence-backed process failures the Working Agreement did not yet
name:

1. **Journey defects surface one per round.** A defect living in a multi-step user
   flow (commit/push gate, onboarding, session lifecycle) was fixed one stop at a
   time, each round exposing the next stop a full end-to-end run would have shown
   together. Measured across BUG-268/272 (one defect per round over ~8–10 rounds),
   with the same shape in BUG-085, BUG-096, FEAT-156.
2. **A complete fix left the user blocked on a commit.** Session 9dd8eb90
   (2026-10-24): the fix was done and demonstrated, but the user waited ~5h for a
   commit clearance that the fixer's own passing demonstration already justified.
   User's words: "commit→it fixes→done", "within 30min instead of 5h".

## Expected
The Working Agreement carries both rules, in its own voice, where fix charters are
built:

1. **Real journey first** (WA §C): for a journey defect, round one drives the user's
   ACTUAL end-to-end flow once and lists EVERY stop it fails at before splitting into
   fixes. This is the charter-level enforcement of §C's existing "verify the
   user-OBSERVABLE outcome".
2. **Unblock the user's commit; verification follows** (WA §J): clear a local commit
   once the fixer's own demonstration passes; run independent verification after; the
   PUSH waits for a HOLDS verdict. Reorders, does not skip.
